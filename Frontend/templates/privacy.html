PRIVACY

Exact fields, and nothing else.

The Windows agent and the model service accept a feature window. Version 1 is keyboard aggregates. Version 2 adds mouse aggregates when mouse collection is enabled. Extra fields are rejected. A score compares a window with that device's enrollment. It is an anomaly signal, not an identity. See what this does not claim.

Window fields

These fields describe the window. They do not name a key or a screen position.

Keyboard features

Every version requires these eleven fields. Pauses are inter-press gaps longer than 1,000 ms. Standard deviations use the population formula. The 90th percentile uses nearest rank. Hold percentiles, press_interval_p50_ms, and burst_length_mean are not accepted and are not collected.

press_interval_mean_msmillisecondsMean time from one press to the next.
press_interval_std_msmillisecondsPopulation standard deviation of press intervals.
press_interval_p90_msmillisecondsNearest-rank 90th percentile of press intervals.

burst_countcountOne more than pause_count. Pauses separate bursts.

What is never collected

The agent may see timing while a password is typed. It still must not record the password. Pause collection before typing one if that timing should stay out of the window. Key identity is discarded before the window is saved.

  • Character sequences, typed text, passwords, search queries, and clipboard contents.
  • Raw scan-code logs, virtual-key-code logs, key names, and per-key frequency tables.
  • Ordered keydown and keyup event streams.
  • Screenshots, application names, browser URLs, and visible page content.
  • Full cursor paths and absolute pointer positions.
  • Input from another person's machine without their informed consent.
